# Exercise media

## Architecture

Four pieces, in the order the app loads them:

| File | Role |
| --- | --- |
| `exercise-media-catalog.js` | Legacy third-party art (Everkinetic), exact-name mapping. Unchanged. |
| `exercise-registry.js` | **Generated.** Canonical exercise per movement: id, name, aliases, equipment, muscles, pattern, `mediaId`. |
| `exercise-media-manifest.js` | **Generated.** One record per media asset: id, tier, style version, status, thumbnail, start, finish, motion, cues, attribution. |
| `exercise-media-resolver.js` | Resolves a name to the best allowed media and reports which tier answered. |

`exercise-registry.js` and `exercise-media-manifest.js` are generated by
`tools/build-exercise-registry.mjs` and committed. Never hand-edit them — they are rebuilt
from the workout definitions, so they cannot drift from the exercises they describe.

## Fallback hierarchy

`IronSixMediaResolver.resolve(name)` returns `{tier, tierName, media, label, via, provisional}`:

| Tier | Meaning | Labelled in UI |
| --- | --- | --- |
| 1 | First-party Iron Six media, exact movement | Only if still `schematic` |
| 2 | Approved legacy media, exact movement | No |
| 3 | Alias-matched exact media | No |
| 4 | Approved canonical variation (same pattern **and** same equipment) | **Yes** — names the substitute |
| 5 | Approved movement-pattern reference | **Yes** — names the substitute |
| 6 | "Demo coming soon" | n/a |

The rule that matters: **tiers 4 and 5 may substitute a different movement, but never
silently.** The card names what it is actually showing. `tests/exercise-media-coverage.test.js`
fails if a substituted asset is rendered without a label naming its source movement.

Supersets resolve each half independently; one half never stands in for the other.

## The Iron Six figure system

First-party art is generated, not drawn. `tools/exercise-art/` contains a small 2D rig:

- `figure.mjs` — the rig. Segment lengths, limb widths, palette, forward kinematics, and
  tapered-capsule limb drawing. One renderer means one silhouette, one palette and one line
  weight across the whole library by construction rather than by review.
- `scene.mjs` — fixed camera (every exercise shares `VIEWBOX`), floor, grounding shadow, and
  reusable equipment parts (barbell, dumbbell, bench, pull-up bar, band).
- `poses.mjs` — the data. Each entry declares the exercise names it depicts, a start and
  finish angle set, the equipment to compose, and the muscles worked.
- `cues.json` — 2–4 form cues and one common mistake per movement.

`node tools/build-exercise-art.mjs` renders every pose to `assets/exercise-art/<id>-start.svg`
and `-finish.svg`. Output is deterministic, so reruns diff cleanly and review is meaningful.
SVG means one file serves thumbnail, start, finish and the motion demo at any density, on web
and Android alike.

### Current status: `ironsix-schematic-v1`

The shipped first-party art is a **schematic**, not finished illustration. It is accurate,
consistent and owned, and it is a real improvement on an empty state, but it does not meet the
commercial-illustration bar. It is therefore tagged `status: "schematic"` in the manifest, is
labelled *"Iron Six schematic — illustration in progress"* wherever it appears, and is counted
separately from professional coverage in every report.

Promoting art to professional means producing a better asset for the same `mediaId` and
flipping `status` to `approved`. Nothing else in the app changes — the registry, resolver and
UI already treat the two identically apart from the label.

## Adding an exercise

1. Add the movement to the workout builder as usual.
2. Add a pose to `tools/exercise-art/poses.mjs` with the exact `names` it depicts, plus cues in
   `cues.json`. A drawing may only claim variants that differ by tempo or pause — never a
   different implement, grip or stance.
3. `node tools/build-exercise-art.mjs && node tools/build-exercise-registry.mjs`
4. `npm test`

Skipping step 2 is caught: a new exercise that lands on tier 6 fails
`tests/exercise-media-coverage.test.js`. The existing backlog is grandfathered in
`reports/media-coverage-baseline.json` and may only shrink. Regenerate that file with
`node tools/build-coverage-baseline.mjs` after coverage genuinely improves.

## Audit

`node tools/exercise-audit.mjs` writes `reports/exercise-media-audit.json` and `.md`: every
exercise the app can show, its coverage bucket, broken references, orphan assets and duplicate
names that should collapse to one canonical movement.

## Legacy art provenance

The PNGs in `assets/exercises/` are unchanged Everkinetic illustrations by Greg Priday,
redistributed from https://github.com/everkinetic/data at revision
`446bb9a3d0c3beb6b84f7c9d77dfc8af707a2ab6` under Creative Commons Attribution-ShareAlike 4.0
(https://creativecommons.org/licenses/by-sa/4.0/). Each record keeps the original filename,
source link, author and licence, and the UI displays attribution beside the image. No
endorsement is implied. Adaptations must retain attribution and use the same licence.

First-party Iron Six art carries no third-party licence and is credited "Iron Six original".
Images are served locally with the app; there is no runtime image search or third-party
hotlink.
